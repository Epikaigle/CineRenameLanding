# 历史记录与撤销 (Undo)

CineRename 在您的磁盘上修改的任何内容都是**可追踪**且**可逆转**的。**历史记录**选项卡就是您的时光机。

## 记录了什么

对于在 Studio、CLI 或自动化流水线中执行的每个重命名批次，CineRename 会记录：

- 精确的**日期和时间**（开始、完成、撤销）
- **批次状态** (`running`、`applied`、`failed`、`undone`)
- 每个文件的完整**修改前 / 修改后**（原始路径与文件名、重命名后路径与文件名、媒体类型）
- 应用的**重命名模板**
- **可撤销性**及校验状态

数据保存在本地 **SQLite** 数据库（Rust 核心通过 `rusqlite` 管理）。绝不向外部服务器或云端发送任何数据。

::: info 历史记录未包含的内容
SQLite 历史表专门记录重命名与移动批次。字幕下载和重复文件清理属于独立操作，不作为可撤销的重命名批次记录。
:::

## 历史记录视图与结构

历史记录界面采用统一的虚拟化列表，按时间顺序分组展示：

- **按日期分组** — 明确区分“今天”、“昨天”以及更早的日期
- **实时搜索** — 可按原始或新文件名/路径快速检索批次和条目
- **状态筛选** — 可查看全部批次、仅可撤销批次、已撤销批次或失败批次
- **排序** — 支持按时间升序或降序切换显示

## 撤销 (Undo)

选择一项操作，然后点击 **撤销 (Undo)**。CineRename 将：

1. 验证文件是否仍然存在于其目标位置
2. 请求确认
3. 恢复原始的名称/位置
4. 在历史记录中将该操作标记为已取消（并创建一个新的“取消”记录）

::: tip 连锁撤销
您可以撤销连续多天的修改——历史记录可以追溯到您安装应用的初始时刻。
:::

## 撤销的限制

在以下情况下，撤销可能会失败：

- 在此期间，文件已被**手动删除**（未放入回收站）。
- 您在 CineRename 处理之后，**手动重命名**了文件——撤销功能无法知道这是同一个文件。
- **源磁盘**不再挂载（NAS 已断开、USB 闪存盘被拔出）。

在这些情况下，CineRename 会报告失败，并保留原始记录以供参考。

## 多选

按住 `Ctrl + 点击`（或 `Cmd + 点击`）可选择多项操作，然后点击 **取消选择 (Undo selection)**。为了尊重操作之间的依赖关系，撤销会以相反的顺序 (LIFO，后进先出) 执行。

也可以在搜索框之外按 `Ctrl+A`（macOS 上为 `Cmd+A`）来选择或清空所有可恢复批次。

## 重置本地历史

桌面应用不会把历史同步到云端。如果需要从零开始，请先备份重要内容，必要时从 **偏好设置 → 支持** 复制诊断信息，然后删除系统中的 CineRename 本地数据文件夹。删除历史也会移除撤销旧操作的能力。
